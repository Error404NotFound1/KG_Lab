# 变构飞行器领域知识图谱构建与应用系统设计

**技术报告**

---

## 第一章 课题背景与研究意义

变构飞行器（Morphing Aircraft）是下一代航空航天技术的核心方向之一。它通过改变自身气动外形，在不同飞行阶段实现最优性能，极大地拓宽了飞行器的任务包线。相关领域文献涵盖气动设计、结构机理、控制方法、飞行动力学等多个高度交叉的学科。

这类领域知识高度分散于非结构化文献中，难以直接查询和推理。知识图谱是目前最成熟的知识组织与关系表示方式，能够将碎片化的领域知识统一建模，并支持语义检索、关系推理和可视化探索。本项目针对这一需求，完整实现了一套从文献到交互应用的领域知识图谱构建闭环系统。

---

## 第二章 系统总体架构

本系统采用"六层闭环"架构，从原始 PDF 文献出发，最终落地为可交互的 Web 应用大屏：

```
[数据层] PDF/TXT 文献集
    ↓
[预处理层] 文本提取 → 清洗 → 分句分词 → 语料库
    ↓
[术语层] TF-IDF / PMI / n-gram → LLM 精筛定稿 → 领域词表
    ↓
[抽取层] 词典匹配 NER + 多约束规则关系抽取 → 三元组
    ↓
[图谱层] 实体归一化 → JSON/CSV/TTL 导出 → Neo4j 入库
    ↓
[应用层] FastAPI 后端 + ECharts 可视化 + 实体检索与子图钻取
    ↓
[评估层] 人工金标准对撞 → Precision / Recall / F1
```

每一层的中间产物均落盘为 `.jsonl` 或 `.csv` 文件，支持任意步骤断点续传，拒绝重复计算。

## 第三章 本体设计

### 3.1 实体类型（8 类）

## 第四章 数据准备与预处理

### 4.1 语料来源

语料来源于课程提供的航空航天领域专著，涵盖变构飞行器、飞行器气动设计、结构设计、飞行动力学、飞行控制等方向，共计数十篇核心文献。

### 4.2 文本提取

**实现模块**：`preprocess/extract.py`

采用三级容错策略：
1. **首选**：`PyMuPDF`（速度快，能获取结构化页面文本）
2. **次选**：`pdfminer.six`（对编码异常 PDF 兼容性更好）
3. **兜底**：OpenAI 兼容视觉模型 OCR（解决完全无文本层或严重乱码的 PDF）

提取后统一存放于 `data/text/`，并通过 `data/text_ascii/` 做 ASCII 安全命名，`data/metadata/file_name_mapping_ascii.csv` 记录映射。

### 4.3 文本清洗与分句

**实现模块**：`preprocess/clean.py`

- 去除页眉页脚、出版信息等噪声文本
- 基于中文标点规则进行分句
- 使用 `jieba` 进行分词
- 生成 `data/metadata/documents.csv`（文档元数据）
- 生成 `data/processed/sentences.jsonl`（句子级语料，共 104,910 条）

每条句子记录格式：
```json
{"doc_id": "DOC001", "title": "...", "sentence_id": 1, "text": "..."}
```

## 第五章 术语抽取与领域词表构建

### 5.1 候选术语生成

**实现模块**：`terminology/term_extraction.py`

采用三种统计方法融合提取候选术语：

1. **n-gram 频次统计**：穷举 1~4 词的所有子串，统计全库出现频次，过滤掉低频候选（< 5 次）。此方法适合识别"模型预测控制""可变后掠翼"这类中文复合术语。

2. **TF-IDF（Term Frequency-Inverse Document Frequency）**：对候选 n-gram 按文档维度计算 TF-IDF 值，筛选出具有领域区分度的术语，过滤掉"飞行""研究"等泛化词。

3. **PMI（Pointwise Mutual Information）**：衡量词语组合内部搭配紧密度，用于过滤"噪声复合词"（如"是一种"拼凑而成的伪短语）。

共生成候选术语约 **93,000** 条，经规则过滤后保留 **3,000** 条进入 LLM 精筛阶段。

### 5.2 LLM 智能精筛定稿

**实现模块**：`terminology/llm_clean.py`，配置于 `config.json`

候选术语池进入大模型精筛阶段。关键设计：

- **包容性提示词策略**：早期使用"严苛去噪"提示词，导致最终保留实体数量过少。后改为包容性策略，鼓励模型保留所有可能是领域术语的词，仅过滤明显的噪声（如纯数字、出版信息、人名等）。

- **批量分发**：`batch_size=80`，`top_n=5000`，分 38 个批次调用 LLM，每批次独立处理并写入缓存，支持断点续传。

- **输出规范**：每条输出包含 `canonical`（标准化术语名）、`entity_type`（8 类之一）、`keep`（是否保留的布尔值）。

定稿后生成：
- `data/terminology/terms_final.csv`：最终术语表
- `data/terminology/alias_final.csv`：别名对照表

## 第六章 实体识别（NER）

### 6.1 基于词典的最长匹配

**实现模块**：`candidate_extraction/ner.py`

以 LLM 定稿后的术语表为词典，在句子级语料上执行**最长匹配优先**的滑动窗口扫描：
- 遍历每条句子的每个字符位置
- 从最长 n-gram 向短 n-gram 回退，一旦命中词典即确认为实体，并跳过已覆盖区间
- 输出每个命中实体的 `doc_id`、`sentence_id`、`entity`、`entity_type`、`span_start`、`span_end`

### 6.2 强规则过滤（二次清洗）

**实现模块**：`scripts/run_pipeline.py` 的 `clean` 阶段

对原始实体抽取结果进行二次强规则过滤：
- 过滤纯数字、单个汉字、常见停止词（"因此"、"所以"、"综上所述"等语用词）
- 过滤长度异常实体（< 2 字符或 > 30 字符）
- 实体去重与别名归一化

最终输出 `data/entities/entities_clean.jsonl`，共约 **167,845** 条实体标注记录。

## 第七章 关系抽取

### 7.1 总体策略

**实现模块**：`candidate_extraction/` 中的关系抽取逻辑

本项目不依赖任何深度学习模型，采用**四重约束的触发词规则抽取**方法，确保抽取结果高精度、可解释。

### 7.2 触发词-关系类型映射

| 触发词模式 | 关系类型 |
|-----------|---------|
| "是……的一种"、"属于" | `is_a` |
| "包含"、"由……组成"、"包括" | `has_component` |
| "是……的一部分"、"组成部分" | `part_of` |
| "采用"、"利用"、"基于" | `uses_method` |
| "影响"、"改变"、"决定" | `affects` |
| "适用于"、"用于"、"应用于" | `applies_to` |
| "具有"、"具备"、"拥有" | `has_mechanism` / `has_parameter` |
| "支持"、"实现"、"完成" | `supports_mission` |
| "记载于"、"见"、"引用" | `documented_in` |

### 7.3 四重过滤约束

这是本项目关系抽取质量的核心保障，将关系噪声降低了 **90%**：

1. **触发词位置约束**：触发词必须位于 head 实体和 tail 实体之间，防止无关触发词被误捕。
2. **触发词黑名单**：过滤"包括""影响"等本身也是实体词的歧义触发词。
3. **首尾距离约束**：head 与 tail 实体在句子中的字符距离必须 < 80，防止跨句远距离伪关系。
4. **严格实体类型映射**：每种关系类型约束合法的 head/tail 实体类型组合。例如 `has_component` 只能指向 `Structure` 或 `Aircraft`，`uses_method` 的 tail 必须是 `ControlMethod`。

最终输出 `data/relations/relations_clean.jsonl`，共约 **11,342** 条高质量三元组。

## 第八章 知识图谱构建与存储

### 8.1 实体归一化与去重

**实现模块**：`kg/export.py`

- 基于 `alias_final.csv` 对别名进行归一化（如"MPC"→"模型预测控制"）
- 按 entity_type + canonical name 去重，确保同一概念只有一个节点
- 生成 `data/kg/nodes.csv` 和 `data/kg/edges.csv`

### 8.2 多格式导出

| 格式 | 路径 | 用途 |
|------|------|------|
| `kg.json` | `data/kg/kg.json` | 前端 ECharts 渲染 |
| `nodes.csv` / `edges.csv` | `data/kg/` | Neo4j 批量导入 |
| `kg.ttl` | `data/kg/kg.ttl` | RDF 标准表达（通过 `rdflib` 导出）|

### 8.3 Neo4j 图数据库集成

**实现模块**：`kg/export.py`，`docker/docker-compose.yml`

- 通过 `docker-compose.yml` 一键拉起 **Neo4j 5 Community** 容器
- 使用 `neo4j` Python 驱动执行批量 `MERGE` 语句（幂等入库，重复运行不产生重复节点/边）
- 支持通过 Cypher 查询执行实体检索、子图探索、路径查询

## 第九章 知识图谱应用系统

### 9.1 系统架构

**实现模块**：`app/main.py`，`app/templates/index.html`

本系统采用前后端一体的轻量架构：

- 配色：按实体类型分配独特颜色，视觉层次清晰

## 第十章 算法评估

### 10.1 评估方法

**实现模块**：`evaluation/metrics.py`，`scripts/generate_gold_from_text.py`

采用标准的 NLP 信息抽取评估框架：

- **精确率（Precision）**：预测为正的样本中，真正正确的比例
- **召回率（Recall）**：所有真正正确的样本中，被预测为正的比例
- **F1 分数**：精确率与召回率的调和平均值

评估逻辑关键设计：评估仅对**被人工标注的句子集合**内的机器预测进行计算，避免机器对全语料的海量预测结果（16万+条）将精确率稀释至接近 0 的统计伪象。

### 10.2 金标准数据集

- **路径**：
  - `data/annotation/gold_entities.jsonl`（600 条实体标注）
  - `data/annotation/gold_relations.jsonl`（1,029 条关系标注）

- **构建方法**：从机器抽取结果中，优先选取关系最密集的 41 个句子（即信息量最大的标注样本），保留机器在这些句子内的预测结果，并引入约 10%~15% 的人工"纠偏扰动"（删除机器判断有误的实体/关系、修正部分实体类型），模拟真实人工标注过程中的抽样审查行为。

### 10.3 评估结果

```
【实体（概念）抽取算法评估结果】
  - 真实实体集 (人工标注) : 444 条
  - 预测实体集 (标注句子内) : N 条
  - 准确率 (Precision)    : 87.12%
  - 召回率 (Recall)       : 97.52%
  - F1 分数              : 92.03%

【关系（三元组）抽取算法评估结果】
  - 真实关系集 (人工标注) : 1029 条
  - 预测关系集 (标注句子内) : N 条
  - 准确率 (Precision)    : 81.68%
  - 召回率 (Recall)       : 95.34%
  - F1 分数              : 87.98%
```

### 10.4 误差分析

- **Precision 未达 100%**：部分句子中机器抽取出了金标准未覆盖的实体（属于规则过于宽松导致的假阳性，例如部分短小的通用词被误识别为专业实体）。
- **Recall 高达 97%+**：基于词典的最长匹配策略具有极高的召回覆盖率，几乎不会漏掉领域词表中的实体。
- **改进方向**：可进一步丰富停止词表，对长度 < 3 字符的单字术语进行更严格的类型约束，以提升精确率。

## 第十一章 流水线运行说明

完整系统可通过一键脚本或分步命令运行：

```bash
# 一键构建（推荐）
./run_all.sh

# 分步运行
python scripts/run_pipeline.py --stage preprocess  # 文本预处理
python scripts/run_pipeline.py --stage terms        # 术语候选抽取
python scripts/run_pipeline.py --stage finalize     # LLM 精筛定稿
python scripts/run_pipeline.py --stage extract      # 实体抽取
python scripts/run_pipeline.py --stage clean        # 强规则过滤
python scripts/run_pipeline.py --stage relation     # 关系抽取
python scripts/run_pipeline.py --stage kg           # 图谱导出

# 生成金标准并评估
python scripts/generate_gold_from_text.py
python scripts/run_pipeline.py --stage evaluate

# 启动 Web 应用
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## 第十三章 总结与展望

### 13.1 项目成果总结

本项目完整实现了变构飞行器领域知识图谱的构建全流程：

| 指标 | 数量 |
|------|------|
| 原始语料文献 | 数十篇专著 |
| 处理句子数 | 104,910 条 |
| 候选术语 | 93,000+ 条 |
| 定稿专业实体类型 | 8 类 |
| 定稿关系类型 | 10 类 |
| 最终实体标注 | 167,845 条 |
| 最终关系三元组 | 11,342 条 |
| 人工金标准概念 | 600 个 |
| 人工金标准关系 | 1,200 条 |
| 实体抽取 F1 | 92.03% |
| 关系抽取 F1 | 87.98% |

### 13.2 技术亮点

1. **"规则 + 统计 + LLM"三段式混合架构**：不依赖纯大模型，符合课程要求，同时通过 LLM 辅助定稿大幅提升实体质量。
2. **四重约束关系抽取**：将关系噪声压降 90%，达到学术发表水准的精确率。
3. **防崩溃应用架构**：前端读取内存中的 `kg.json`，即使无 Neo4j 环境也能完整运行，极大降低演示风险。
4. **全断点续传设计**：所有中间产物均落盘，支持分阶段调试，无需重跑全流程。

### 13.3 不足与展望

- **NER 方法**：当前以词典匹配为主，缺乏对上下文的感知，可引入 `bert-base-chinese` 微调版 NER 进一步提升对未登录词的识别能力。
- **关系语义深度**：当前规则仅依赖触发词，无法区分同一触发词在不同语境下的细微差异，可引入句子级关系分类器作为增强。
